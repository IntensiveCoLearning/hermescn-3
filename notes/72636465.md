# 2026-09-05

**配置教程：Windows 原生 Hermes Desktop + WSL2 后端**\
\
**一、动机**\
\
**目前现状：** Hermes 装在 WSL2 的 `~/.hermes`，所有个人数据——profile、skills、memory、会话记录、cron 任务——都在这个目录里。TG gateway 也是 WSL 里的 systemd 服务，7×24 在跑。\
\
**核心矛盾：** Windows 原生 Desktop 会用 `%LOCALAPPDATA%\hermes` 作为自己的配置目录——那是一个**全新的、空的** HERMES\_HOME。如果直接在 Windows 装了开始用，会形成**两套割裂的配置**（split-brain）：\
\
**配置目录**\
• WSL 里的 Hermes: `~/.hermes`\
• Windows 原生安装: `%LOCALAPPDATA%\hermes`\
\
**Skills/Memory**\
• WSL 里的 Hermes: ✅ 现有的全部积累\
• Windows 原生安装: ❌ 空\
\
**会话历史**\
• WSL 里的 Hermes: ✅ 完整\
• Windows 原生安装: ❌ 空\
\
**TG gateway**\
• WSL 里的 Hermes: ✅ 在跑\
• Windows 原生安装: ❌ 无\
\
**Desktop 的架构给了第三条路：** Desktop 本质是一个 UI 壳，它通过 JSON-RPC/WebSocket 连接一个 `hermes serve` 后端进程。后端在哪，数据就在哪。所以：\


```
┌─────────────┐   WebSocket    ┌──────────────────────────────┐
│ Windows      │ ←────────────→ │ WSL2                          │
│ Hermes       │  localhost:9119 │  ├─ hermes serve (后端)       │
│ Desktop(纯UI) │                │  ├─ hermes-gateway (TG,不动)  │
└─────────────┘                 │  └─ ~/.hermes (全部数据,不动)  │
                                └──────────────────────────────┘

```

\
**收益：** 原生 Windows UI 的流畅体验（不依赖 WSLg 的 Electron 显示）、数据零迁移、TG gateway 与后端共存于同一份数据源、Desktop 上创建的 Bot（Bot Mode）会直接成为 WSL 里的新 profile。\
\
**二、前置条件**\
\
- Hermes 版本 ≥ 支持 `hermes serve`\
- Windows 侧已安装 Hermes Desktop（从 [官网](https://hermes-agent.nousresearch.com/desktop) 下载）\
\- 端口 9119 未被占用\
\
**三、操作流程**\
\
**第 1 步：配置后端认证（WSL 内）**\
\
Desktop 连接时需要登录凭据。绑定到非 loopback 地址会自动启用认证门，所以凭据必须先配好：

```
# 先检查是否已有相关变量（避免重复追加）
grep DASHBOARD ~/.hermes/.env

# 没有的话，追加（把密码换成强密码）
cat >> ~/.hermes/.env <<'EOF'
HERMES_DASHBOARD_BASIC_AUTH_USERNAME=***
HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=***
# 固定签名密钥：不设的话每次重启后端都会被登出
HERMES_DASHBOARD_BASIC_AUTH_SECRET=*** rand -base64 32)
EOF

chmod 600 ~/.hermes/.env

```

<br />

> 注意：cat >> 里 $(openssl ...) 会立即求值并写入结果，之后**不要重复执行这段**，否则会追加重复变量。想不留明文密码，可用 scrypt 哈希替代：

```
> python -c "from plugins.dashboard_auth.basic import hash_password; print(hash_password('你的密码'))"
> # 用 HERMES_DASHBOARD_BASIC_AUTH_PASSWORD_HASH=*** 代替 PASSWORD 行
> 
```

\
**第 2 步：启动** `hermes serve`\
\
**先手动启动验证一切正常：**\


```
hermes serve --host 0.0.0.0 --port 9119

```

\
\
看到服务就绪后，`Ctrl+C` 停掉，固化成 systemd 常驻服务（和你现有的 hermes-gateway 同款方式）：\


```
# 创建 ~/.config/systemd/user/hermes-serve.service
[Unit]
Description=Hermes Agent Backend (serve)
After=network.target

[Service]
Type=simple
ExecStart=%h/.hermes/hermes-agent/venv/bin/python -m hermes_cli.main serve --host 0.0.0.0 --port 9119
EnvironmentFile=%h/.hermes/.env
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target

```

<br />

```
systemctl --user daemon-reload
systemctl --user enable --now hermes-serve
systemctl --user status hermes-serve --no-pager

```

\
\
**第 3 步：确认 Windows → WSL 可达**\
\
WSL2 默认开启 localhost 转发（Windows 的 localhost:9119 → WSL）。在 **Windows PowerShell** 里验证：

```
Invoke-RestMethod http://localhost:9119/api/status
```

\
应返回包含 `auth_required: true` 和 `auth_providers` 含 `basic` 的 JSON。

> 若不通：检查 \~/.wslconfig 里 localhostForwarding 是否被关了；备选方案是用 WSL 的 eth0 IP（ip addr show eth0，但该 IP 重启后会变）。

\
**第 4 步：Desktop 连接后端（Windows）**\
\
1. 打开 Hermes Desktop → **Settings → Gateways**\
2. Connection mode 选 **Remote gateway**\
3. Remote URL 填 `http://localhost:9119`\
4. 点 **Sign in**，输入第 1 步的用户名密码\
5. **Save and reconnect**\
\
登录成功后，左侧 profile 栏应显示你 WSL 里的 profile（`default`）。\
\
**四、验证清单**\
\
**1**\
• 验证项: 后端健康\
• 方法: WSL: `curl -s http://localhost:9119/api/status`\
• 预期: `auth_required: true`，providers 含 `basic`\
\
**2**\
• 验证项: 服务常驻\
• 方法: `systemctl --user status hermes-serve`\
• 预期: active (running)\
\
**3**\
• 验证项: Windows 可达\
• 方法: PowerShell 第 3 步命令\
• 预期: 返回 JSON\
\
**4**\
• 验证项: **数据继承**\
• 方法: Desktop 会话列表\
• 预期: 能看到你 TG topic 里的历史会话标题\
\
**5**\
• 验证项: Memory 继承\
• 方法: 在 Desktop 里问只有它才知道的事\
• 预期: 能答出\
\
**6**\
• 验证项: Skills 继承\
• 方法: Desktop 的 Skills 面板\
• 预期: 列出已安装的全部 skills\
\
**7**\
• 验证项: TG 不受影响\
• 方法: 发一条 TG 消息\
• 预期: 照常回复，且该会话出现在 Desktop 会话列表里\
\
**8**\
• 验证项: 重启持久\
• 方法: `wsl --shutdown` 后重启 WSL\
• 预期: 两个 systemd 服务都自动拉起，Desktop 重连即可

**第 4、7 项是最有说服力的验证**——因为 serve 和 gateway 读的是同一个 SQLite session store，在 TG 里聊的 topic 会话会直接出现在 Desktop 的 Sessions 列表里，这就是"同一份数据"的直接证据。\
\
**五、踩坑与常见问题（来自官方文档）**\
\
- **401 / Invalid credentials** — `.env` 里的用户名密码和输入不一致。后端对"用户不存在"和"密码错误"返回同样的错误（防枚举），两个都要核对\
- **没有 Sign in 按钮，要求输 session token** — 后端没加载到 basic 认证配置，检查 systemd unit 的 `EnvironmentFile` 行和 `.env` 变量名拼写\
- **每次重启后端都被登出** — `HERMES_DASHBOARD_BASIC_AUTH_SECRET` 没设或每次变化\
- **Connection refused** — serve 进程没起来，或绑在了 127.0.0.1（用 `--host 0.0.0.0`）\
- **不要动 gateway 服务** — `hermes serve` 和 `hermes-gateway` 是两个独立进程，谁也不依赖谁，但共享同一个 HERMES\_HOME\
- **更新** — Desktop 里 Update Hermes 会先更新 WSL 后端再更新 Desktop 本身，一条龙完成\
\
**六、日常运维**

```
hermes serve --status          # 查看后端状态
hermes serve --stop            # 停止（手动模式时）
systemctl --user restart hermes-serve   # 服务模式重启
hermes logs gui -f             # Desktop 相关日志在 WSL 侧查看
```
