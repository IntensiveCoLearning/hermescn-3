# HermesCN第二期第1天打卡（2026-09-03）

**学习时长：1小时**

## 今日学习与实践

今天重点梳理了Hermes多层上下文与记忆系统的运作逻辑，明确区分：

- Telegram Topic：长期稳定的主题入口；
- Hermes Session：当前会话历史，可通过`/new`重新开始；
- 工作目录：项目文件和工具操作的边界；
- Project Context：项目级持久规则，在进入相关项目时加载；
- 长期记忆与跨Session检索：分别承担稳定事实保存和历史信息按需查找。

在这个认知基础上，我为两个长期主题建立了独立项目工作区和Topic精确路由。实际使用`/new`验证了其中一个主题：新Session能够重新恢复到原来的项目上下文，说明Topic可以保持长期项目归属，而Session可以按需更新，两者不必绑定为同一个生命周期。

同时，我定位了`/new`后Topic名称被首个问题覆盖的原因：这是Hermes的Session自动标题机制触发了Topic重命名，而不是Telegram客户端的原生行为。随后启用了保留手工Topic名称的专用配置，并完成配置解析验证；最终用户可见行为仍需在Gateway重新加载配置后实测。

## 最有价值的发现

今天最有价值的发现，是对多层记忆系统中的运作逻辑有了清晰认知。过去容易把Topic、Session、工作目录、项目规则和长期记忆混在一起，现在更清楚它们各自解决什么问题，以及它们如何组合：长期主题负责入口，Session负责短期对话，项目上下文负责稳定边界，长期记忆和历史检索负责跨项目、跨会话的信息延续。

这也让我认识到，可靠的Agent系统不能只看“文件是否写入”或“配置命令是否成功”，还要验证新Session能否恢复、运行时是否真正加载，以及最终用户看到的行为是否符合设计。

# HermesCN第二期第3天打卡（2026-09-05）

## 学习时长

0.5小时。

## 今日学习

今天围绕“模型的工具调用能力”进行了讨论，重点区分模型、Agent框架、Tool、Skill、外部程序和系统权限各自承担的职责。

模型主要负责理解目标、选择工具、构造参数、规划多步动作、解释返回结果、错误恢复，以及判断何时继续验证或停止。Tool回答“系统实际能执行什么动作”，Skill回答“面对某类任务，应如何组合工具并遵守什么流程”。Skill本身不是模型内置的实际工具；只有执行工具、外部程序、权限和环境同时可用时，Skill描述的能力才能真正落地。

工具调用格式正确只是最低门槛。可靠的Agent还需要保持参数和状态一致，识别不完整证据，正确处理错误，并在写操作后回读目标。稳定统计、关键执行和重复校验适合由确定性脚本完成，模型则更适合负责自然语言理解、动态选择和异常判断。

## 今日感悟

不同模型的工具调用能力差异很大。工具调用能力强的模型，能够更准确地选择工具、构造参数、理解返回结果并完成验证，因此处理Agent任务时通常效率更高、可靠性也更好。

## 与本期项目的关系

“Skills可观测与治理MVP”需要准确区分模型决策、Tool执行、Skill指导和外部状态。后续可以从工具识别、参数构造、多步规划、结果理解、错误恢复、状态管理、验证与停止七个维度，观察和比较模型的工具调用表现。
